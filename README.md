# НОВАЯ ЖИЗНЬ v5 — GitHub Pages + Railway + PostgreSQL

## Что внутри

- `index.html` — полный мобильный интерфейс. Картинки встроены внутрь HTML, поэтому для GitHub Pages достаточно **одного файла**.
- `server/main.py` — рабочий FastAPI-сервер: регистрация, авторизация, PostgreSQL, персонажи, ежедневная экономика, бизнесы, админ-панель.
- `server/requirements.txt`, `server/railway.json`, `server/Procfile` — файлы для Railway.
- `assets/` — оригиналы изображений, если захочешь изменить оформление позже.

## Установка на GitHub Pages

1. Распакуй ZIP.
2. В `KatasAdmin/new` замени файл **`index.html`** в корне ветки `main` на новый из архива.
3. **Также добавь папку `server/`** с файлами из ZIP в тот же репозиторий, если её там ещё нет. Файлы `server/` нужны Railway, но GitHub Pages их не использует.
4. Сайт: https://katasadmin.github.io/new/

Важно: GitHub **не распаковывает ZIP** при обычной загрузке в репозиторий. ZIP сначала нужно распаковать на устройстве и загрузить нужные файлы. Изображения в `assets/` для запуска не требуются.

## Railway — подключить настоящую базу

1. Railway → **New Project → Deploy from GitHub Repo** → `KatasAdmin/new`.
2. Добавь сервис **PostgreSQL** в тот же проект через **New → Database → PostgreSQL**.
3. У сервиса приложения укажи **Root Directory = `/server`** (это важно).
4. В переменных сервиса приложения создай:
   - `DATABASE_URL` — **Reference** на `DATABASE_URL` сервиса PostgreSQL (не вводи выдуманный URL).
   - `ALLOWED_ORIGINS` = `https://katasadmin.github.io`
   - `ADMIN_BOOTSTRAP_SECRET` = длинная случайная строка от 16 символов (храни только в Railway, никому не отправляй).
5. У приложения **Settings → Networking → Generate Domain**. Получится HTTPS-адрес вида `https://...up.railway.app`.
6. Проверь в браузере `https://ТВОЙ-ДОМЕН/api/health`: должен ответить `{"ok":true,"database":"connected","version":"5.0"}`.
7. Открой игру → ⚙️ → вставь **адрес сервера без `/api/health`** → «Сохранить и проверить соединение».
8. Создай первый аккаунт. В поле «Секрет первого администратора» введи значение `ADMIN_BOOTSTRAP_SECRET` из Railway. Этот аккаунт получит ID `00000001`, 18 лет, все программы образования и серверную роль `admin`. Остальные игроки не вводят секрет, начинают в 16 лет.

**Не используй SQLite на Railway в продакшене.** Он предназначен только для локальных проверок; без PostgreSQL данные могут пропасть при пересоздании контейнера. Перед публичным запуском настрой резервное копирование PostgreSQL.

## Экономика

- Один игровой год = два реальных дня; зарплата и расходы — раз в 24 часа.
- Работа продолжается без посещений. Сервер обрабатывает пропущенные сутки при обращении и фоновым заданием примерно каждый час.
- Стаж и повышения: 7 / 21 / 45 смен, ставки от 2 до 8 виртуальных ₴ в день.
- Еда, вода, энергия и здоровье — шкалы от 0 до 100. При нехватке еды/воды автопокупка по цене ×2.
- Бизнесы: фиксированные цены и фиксированная прибыль, окупаемость ~35–80 реальных дней.
- Вывод серый, с надписью «В разработке». **Пополнение реальными деньгами отключено**: для него нужны отдельная платёжная интеграция и проверка вебхуков. Никаких реальных денег сервер не принимает.

## Честные ограничения текущей версии

- Государственная работа функционирует; **частные вакансии и списание зарплат со счетов работодателей пока не подключены**, для них оставлен следующий этап.
- Пока доход предприятий фиксированный, он не зависит от покупок игроков. Это не замкнутая экономика.
- Данные старого `localStorage` **не переносятся автоматически** в PostgreSQL. Создаётся новый серверный аккаунт. Не удаляй старый локальный прогресс до миграции.
- Фотография персонажа — временный иллюстративный портрет для всех игроков. Загрузка личного аватара пока не реализована.
- Для полноценного публичного запуска дополнительно нужны ограничения запросов, подтверждение почты/восстановление пароля, миграции БД, аудит и тестирование нагрузок.
- **Никогда не размещай `ADMIN_BOOTSTRAP_SECRET` в `index.html` или в GitHub.**

## API

- `GET /api/health`, `GET /api/config`
- `POST /api/register`, `POST /api/login`, `GET /api/me`
- `POST /api/action` (`job`, `study`, `food`, `water`, `buy_business`)
- `POST /api/admin/claim`, `GET /api/admin/users`, `POST /api/admin/edit`

Авторитетное состояние и деньги хранятся в PostgreSQL. Браузер не может напрямую установить себе баланс. Пароли хешируются PBKDF2-HMAC-SHA256, токены хранятся на сервере в виде SHA-256-хешей. Секреты Railway нельзя публиковать.


## Аватары (v6)
В профиле нажмите на фотографию: 16 готовых вариантов или загрузка своего изображения. Пока аватар сохраняется в localStorage только на данном устройстве, отдельно от серверного профиля. Для синхронизации между устройствами потребуется API загрузки аватара и серверное файловое хранилище.
